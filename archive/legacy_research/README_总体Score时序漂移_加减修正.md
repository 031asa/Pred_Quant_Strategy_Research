# 总体 Score 时序漂移加减修正：首次实测

## 口径

- 冷启动：完整首个自然月，共 21 个交易日。
- 慢速基准：截至前一日的历史日中位数之扩展中位数，会随样本增加而修正。
- 近期中心：历史日中位数的因果 EWMA。
- 加减修正：`adjusted_score = score - ((recent_center + balance_offset) - slow_baseline)`。
- 最终测试：最后 60 个交易日（2026-04-01 至 2026-06-30），不参与选参。
- Tag 不进入参数选择，仅用于事后方向与收益报告。

## 当前分时扩展：14:30前后独立状态

历史总体实验保留不动。当前入口`scripts/总体Score时序漂移.py`将同一方法拆成两个互不共享状态的时段：

- `Datetime < 14:30`为14:30以前；14:30整点及以后归入后一段。
- 每段独立计算日中位数`M_s,t`、扩展中位数慢速基准`B_s,t`、EWMA近期中心`C_s,t`和开发段固定平衡偏移`d_s`。
- 每段的交易日t状态只使用同一时段、严格早于t的交易日数据。
- 每段分别在1、2、5、10、20、40、60、90和120日半衰期中选参；两段均选中1日，alpha均为0.5。
- 每段开发段修正后做空占比均校准为50%；Tag不参与选参。
- 修正前按`score < B_s,t`做空，修正后按`score < C_s,t + d_s`做空。

## 一、问题是什么

固定首月中位数会把冷启动误差永久固化。例如首月整体偏高，即使后续样本表明长期正常中心更低，固定基准仍会一直偏高。这里把问题拆成两部分：慢速基准负责随着历史样本增加而修正长期锚点，快速中心负责描述近期Score整体漂到了哪里。两者之差才是需要从每条Score中消除的时序偏移。

本方法只做平移，不缩放Score，也不改变同一天样本之间的排序。它解决的是Score整体中心随时间漂移的问题，不直接保证Tag方向、胜率或收益改善。

## 二、符号与因果约束

- `score = clip(pred + 0.5, 0, 1)`。
- `M_t`：第t个交易日全部样本Score的中位数。
- `B_t`：交易日t开盘前可得的慢速基准。
- `C_t`：交易日t开盘前可得的近期EWMA中心。
- `d`：仅用开发段估计、之后固定不变的多空平衡偏移。
- 所有用于交易日t的状态只使用严格早于t的数据；当天的Score不会参与当天的基准或修正值。

## 三、第一条线：会自我修正的慢速基准

冷启动使用首个完整自然月。本数据从2024-01-03开始，首月共有21个交易日，因此第一次产生可用状态是在2024-02-01。此后：

```text
B_t = median(M_1, M_2, ..., M_{t-1})
```

它不是把2024年1月的中位数永久冻结，而是每天用截至昨日的全部历史日中位数重新计算。首月若偏高，后续更多正常月份进入后，`B_t`会逐步向真实长期中心修正；历史越长，单个新交易日对`B_t`的影响通常越小。选择日中位数而不是直接汇总全部分钟样本，也避免某个交易日因样本更多而获得更大权重。

扩展中位数的代价是反应较慢。这是刻意设计的：它承担长期锚点，而不是追逐短期行情。

## 四、第二条线：跟踪近期漂移的快速中心

冷启动后的首个可评估日令 `C_t = B_t`；之后每天只吸收昨日的日中位数：

```text
C_t = (1 - alpha) * C_(t-1) + alpha * M_(t-1)
alpha = 1 - 2^(-1 / h)
```

其中`h`是半衰期。`h`越小，`C_t`越贴近最近市场，漂移纠正更快但日级修正更跳；`h`越大，`C_t`越平稳，但对新漂移反应更慢。候选半衰期为1、2、5、10、20、40、60、90和120个交易日。

## 五、平衡偏移与最终加减修正

对每个半衰期，只在开发段计算一个固定加法项：

```text
d = median(score - C_t)  （仅开发段）
E_t = C_t + d            （有效中心）
offset_t = E_t - B_t     （当天需要消除的漂移）
adjusted_score = score - offset_t
```

因为`d`是开发段`score-C_t`的中位数，所以在没有大量并列值时，`score < E_t`与`score >= E_t`会把开发段样本约分成50%做空和50%做多。这就是多空均衡进入算法的方式。当前候选全部达到50%，因此49%至51%的硬约束在本轮主要起安全检查作用。

修正后的判断仍以慢速基准为轴：

```text
adjusted_score < B_t  做空，否则做多
```

代入上式可得它完全等价于`score < E_t`。因此可以把算法理解为两种等价视角：图上移动Score、保留慢基准；或保留原Score、使用随时间变化的有效阈值。这里选择前者，是为了直接观察月度分位数曲线是否被压平。

举例：若`B_t=0.485`、`C_t=0.500`、`d=0`，则近期中心比长期基准高0.015，所有Score统一减0.015；若近期中心低于基准，则统一加回相应差值。因为同一天所有样本加减相同，日内排序和当天等分排名不会改变。

## 六、怎样选择半衰期

数据按时间切分：首个完整自然月只做冷启动；最后10%、即60个交易日作为最终测试集；中间519个交易日为开发段。测试段不参与半衰期或`d`的估计。Tag也不参与选参，只在确定方案后用于事后评价。

先要求开发段做空占比位于49%至51%，再依次最小化：

```text
月度面积 = mean(|每月 adjusted_score 相对 B_t 的中位偏移|)
月度斜率 = mean((相邻两月中位偏移之差)^2)
```

面积衡量曲线整体离零轴有多远；斜率衡量相邻月份是否剧烈跳动。这里的“面积”是等间隔月份上的离散绝对面积代理，不是对分钟曲线做连续几何三角形积分。最大月度中位偏移和日偏移变化只作为诊断输出，没有进入本轮排序目标。

## 七、本轮结果应该怎样解释

- 选中`h=1`，`alpha=0.50000000`，开发段固定`d=-0.00006722`。
- 开发段月度绝对面积下降68.63%。
- 最终测试段月度绝对面积下降75.50%，月度斜率均方下降91.19%。
- 最终测试段做空占比为49.33%。
- 但测试段平均策略收益由0.00005123降至-0.00003689，总体方向准确率也由50.55%降至50.09%。
- `h=1`的开发段日偏移绝对变化P95为0.026907，最大值为0.047952。

因此，本轮证明了算法能控制月度中心漂移，却没有证明它能提升预测收益。`h=1`胜出，是因为当前目标函数偏重月度贴轴，而日级平滑度没有进入优化；若上线更重视稳定性，应把日偏移变化上限或惩罚项纳入下一轮开发段选择，并继续保持最终测试集封存。

## 八、适用边界

- 这是位置平移，不修正分布宽度、偏度、尾部形态或不同合约间的结构差异。
- 同一天的横截面排序不变，但跨日期汇总排序可能改变。
- 强制开发段50%多空只是校准约束，不代表真实市场方向必然各占50%，也不代表收益最优。
- 慢基准、快中心和固定`d`都不能使用未来数据；实盘必须按日顺序更新。
- 历史总体基准为全体样本统一修正；当前分时扩展已经按14:30前后分别估计状态，两套结果同时保留。
- Tag仅用于事后检验，且当前结果未扣除手续费、滑点和资金占用。

## 九、完整流程

```text
原始pred -> score -> 每日日中位数M_t
                    |-> 历史扩展中位数B_t（长期锚点）
                    |-> 因果EWMA中心C_t（近期状态）
开发段score-C_t -> 固定平衡偏移d
E_t=C_t+d -> offset_t=E_t-B_t -> adjusted_score=score-offset_t
开发段选h -> 冻结h和d -> 最后60日测试 -> Tag事后评价
```
